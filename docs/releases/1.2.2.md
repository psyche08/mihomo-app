MihomoBox 1.2.2 bundles a Mihomo core with MASQUE CONNECT-UDP, keeps Mihomo starting after boot on installations with outdated LaunchDaemon settings, keeps App Proxy listeners after a repair install and adds profile deletion to `mihomoboxctl`. 1.2.1 was not published; its changes are included here.

- The bundled core is Mihomo v1.19.30 with one patch adding RFC 9298 CONNECT-UDP to `h3-l4proxy` MASQUE nodes that set `udp-uri`, so UDP travels in HTTP datagrams on the same HTTP/3 connection as TCP. Nodes without `udp-uri` behave as upstream. A tunnel the proxy ends is reopened, tunnel setup is bounded to 10 seconds, and a tunnel that sends for 30 seconds without receiving anything is replaced. The core is built from a pinned commit of the fork and accepted only at its pinned SHA-256 (`v1.19.30-connect-udp.3`).
- Installations made before 1.1.2 still run the old LaunchDaemon definition, whose throttled start could miss the start window after boot and leave Mihomo stopped. The App now compares the installed and bundled definitions and recommends **Repair Daemon Launch Settings…** when they differ; it never opens the administrator dialog by itself. The boot start gets 60 seconds, and a start that times out logs which checks never passed.
- A repair install no longer leaves App Proxy without its `mihomobox-app-*` listeners: at boot the daemon re-renders the active profile when saved routes have no listener in it. Route validation now greets each application port as the extension does and reports `app_proxy_listeners` when one does not answer.
- `mihomoboxctl profile delete NAME` removes a stored profile. The active profile is refused, and only an exactly named regular file is removed.

Developer ID identity, bundle identifiers, Sparkle signing key and historical upgrade trust are unchanged. Releases are signed, notarized and stapled locally.
