MihomoBox 1.1.2 keeps Mihomo resident and makes TUN switching faster, while improving DNS ownership and App Proxy maintenance.

- Keep the proxy kernel and mixed proxy listener running when TUN is disabled. TUN, System Proxy and App Proxy remain independent controls.
- Precreate and retain the TUN interface in the privileged daemon. Mihomo inherits the managed descriptor, and warm switches change traffic routes without recreating the interface or restarting the kernel.
- Remove external DNS latency from local readiness checks, wake validation when a matching health snapshot arrives, and avoid background scheduling delays on interactive transitions.
- Preserve complete route, controller and DNS ownership verification before reporting success. On the acceptance Mac, 20 consecutive warm switches took 90–136 ms; heavy CPU and memory pressure can still increase latency.

- Use the independent loopback DNS bridge in Global DNS fallback, preserving original DNS restoration and historical address migration.
- Debounce bridge failures independently of kernel recovery and back off before reacquiring DNS.
- Renew existing App Proxy authorization independently of macOS preference reads; coalesce renewals and prevent timed-out preference requests from accumulating.
- Keep signature renewal off the socket relay queue while preserving the 90-second lease, signed-code validation and generation checks.
- Preserve Team ID policies, proxy selections, bypasses and saved TUN/App Proxy/System Proxy choices.

Developer ID identity, bundle identifiers, Sparkle signing key and historical upgrade trust are unchanged. Releases are signed, notarized and stapled locally.
